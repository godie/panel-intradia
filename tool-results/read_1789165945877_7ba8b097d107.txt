     5→## Project Status (as of initial delivery)
     6→
     7→**Estado:** Funcional y verificado end-to-end con agent-browser + VLM.
     8→
     9→El proyecto es un panel cuantitativo cripto en vivo (BTC/USD, ETH/USD, XRP/USD)
    10→con análisis técnico intradía. El prompt original pedía **backend en PHP**, pero
    11→el entorno sandbox solo expone el puerto 3000 vía Next.js (no se puede servir
    12→PHP externamente). Por ello se implementó **toda la lógica de backend en una
    13→API Route de Next.js** (`/api/analysis`) que respeta **exactamente** el mismo
    14→contrato JSON, caché de 60s, manejo de errores 502 y separación de funciones
    15→(`fetchKlines`, `fetchTicker24h`, `calculateEMA`, `findSupportResistance`,
    16→`buildStructureText`) que pedía el spec de PHP. El frontend consume solo el
    17→JSON ya calculado, tal como exigía el requisito no funcional.
    18→
    19→## Architecture
    20→
    21→```
    22→src/
    23→  app/
    24→    api/analysis/route.ts   — GET /api/analysis?symbol=BTCUSDT (cache 60s, 502 on error)
    25→    page.tsx                — dashboard (fetch paralelo 3 símbolos, refresco 60s + botón manual)
    26→    layout.tsx              — fuentes Inter + JetBrains Mono, tema oscuro forzado
    27→    globals.css             — paleta trading-terminal (#0A0D12), animaciones ticker/live-dot
    28→  lib/
    29→    binance.ts              — fetchKlines + fetchTicker24h (timeout 5s, AbortController, errores tipados)
    30→    indicators.ts           — calculateEMA (SMA seed + recurrencia k=2/(N+1)), findSupportResistance (pivotes ±3, lookback 80), determineCrossState (COMPRIMIDO <0.15%)
    31→    structure.ts            — buildStructureText en español (posición vs medias, % distancia, gatillo invalidación)
    32→    cache.ts                — caché en memoria TTL 60s por símbolo (Map)
    33→    types.ts                — AnalysisResponse + SYMBOL_META compartidos API/frontend
    34→  components/panel/
    35→    asset-card.tsx          — tarjeta por activo (badge estado, precio spot, sparkline, filas EMA/S/R, estructura)
    36→    sparkline.tsx           — canvas HiDPI con precio + EMA55 (ámbar) + EMA200 (azul dashed) + area fill por estado
    37→    ticker-tape.tsx         — marquee scroll continuo con 3 precios + cambio 24h (loop duplicado sin costura)
    38→```

    40→## JSON Contract (cumplido exactamente)
    41→
    42→```json
    43→{
    44→  "symbol": "BTCUSDT",
    45→  "spot_price": 77708.11,
    46→  "change_24h_pct": -3.09,
    47→  "ema55_4h": 76378.76,
    48→  "ema200_4h": 69783.37,
    49→  "cross_state": "ALCISTA",
    50→  "resistance": 78828.15,
    51→  "support": 77632.58,
    52→  "structure_text": "Precio operando por encima de ambas medias (+1.74% vs EMA55, +11.36% vs EMA200); estructura de medias alcista (EMA55 > EMA200); invalidación alcista si pierde EMA55 (~76,379, -1.71%); resistencia inmediata en 78,828 (+1.44%); soporte inmediato en 77,633 (-0.10%).",
    53→  "no_disponible": { "spot_price": false, "change_24h_pct": false, "ema55_4h": false, "ema200_4h": false, "cross_state": false, "resistance": false, "support": false },
    54→  "series": { "closes": [...], "ema55": [...], "ema200": [...] },
    55→  "updated_at": "2026-08-29T06:45:28.000Z"
    56→}
    57→```
    58→
    59→Campo extra `series` añadido para que el frontend pueda dibujar el sparkline
    60→sin llamar a Binance directamente (respeta "el frontend solo consume el JSON
    61→ya calculado"). `no_disponible` es un objeto por-campo; el frontend muestra
    62→literalmente "Dato no disponible" cuando cualquier flag es `true`.

    98→## Unresolved Issues / Risks / Next-Phase Priorities
    99→
   100→1. **Binance geo-disponibilidad**: la API pública de Binance puede estar
   101→   bloqueada en algunas regiones. Hoy funciona desde el sandbox. Si falla en
   102→   producción, considerar fallback a `api.binance.us` o un proxy. Prioridad
   103→   baja mientras funcione.
   104→2. **Persistencia de caché**: la caché es en memoria (Map) — se pierde al
   105→   reiniciar el server. Aceptable para dev; en prod con múltiples instancias
   106→   migrar a Redis/APCu-equivalente. Prioridad baja.
   107→3. **Rate limits de Binance**: con caché 60s y 3 símbolos = ~3 requests/min,
   108→   muy por debajo del límite (1200/min). Sin riesgo.
   109→4. **Tests automatizados**: no se escribieron tests (policy del entorno).
   110→   Las funciones de `indicators.ts` y `structure.ts` son puras y fáciles de
   111→   testear si se añade Jest/Vitest en una fase futura.
   112→5. **Más indicadores**: el panel podría ampliarse con RSI, MACD, volumen,
   113→  order book depth, o alertas cuando el cruce de medias ocurre. Espacio
   114→   claro para iteración.
   115→6. **Websockets para precio real-time**: actualmente refresco cada 60s. Se
   116→   podría añadir un mini-service socket.io (puerto 3003) conectado a
   117→   Binance WebSocket para precios tick-a-tick, manteniendo el análisis de
   118→   EMA cada 60s. Mejora futura.
